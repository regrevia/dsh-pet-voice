# ASR 延迟与准确率：改前 / 改后

环境：Apple M4 Pro，CPU 推理（MPS 上 large-v3-turbo 的 sparse 算子缺失，跑不起来；本机无外网，
装不了 mlx-whisper / faster-whisper），模型均为 `large-v3-turbo`。
样本：9 条中文语音 × 三档音质 = 27 次请求（干净 / SNR10 / SNR5）。
数据文件：`before_after.json`（改前 prod）、`after_new.json`（改后）。
> 样本是 TTS 合成 + 白噪声 / 带限 / 变调做的口音代理，不是真人录音（线上只留了文本、没留 wav）。

## 总表

| 指标 | 改前（线上 `beam_size=5` + 温度回退阶梯） | 改后（`temperature=0` / `beam=1`） | 变化 |
| --- | --- | --- | --- |
| 单句耗时 中位数 | 2179 ms | **1499 ms** | −31% |
| 单句耗时 平均 | 2677 ms | **1513 ms** | −43% |
| 单句耗时 P90 | 2559 ms | **1639 ms** | −36% |
| 最慢一句 | **9497 ms** | **1829 ms** | −81% |
| 超过 3 s 的请求 | 2 / 27 | **0 / 27** | 消除长尾 |
| 冷启动到可服务 | 10686 ms | **6762 ms** | −37% |
| 平均字错率 CER | 0.082 | **0.003** | −96% |
| 完全正确（CER=0） | 21 / 27 | **25 / 27** | +4 |
| 返回空文本（说了没反应） | 2 / 27 | **0 / 27** | 消除 |

## 分档（平均 CER / 空结果）

| 音质 | 改前 | 改后 |
| --- | --- | --- |
| 干净（9 句） | 0.000 / 0 空 | 0.000 / 0 空 |
| SNR10（9 句） | 0.128 / 1 空 | **0.010 / 0 空** |
| SNR5（9 句） | 0.118 / 1 空 | **0.000 / 0 空** |

改前的两个空结果都是 0.72 s 的短句「可以啊」（SNR10 等了 **9497 ms**、SNR5 等了 **8493 ms** 之后返回空）；
改后同一句在 1347–1478 ms 内正确返回。

## 改后仅剩的 2 处错字（都在 SNR10 强噪声下）

- `s6`「局域网，能够**扫**码直接用吗?」→「**小**码」：谐音近音，干净音质下正确。
- `s9`「我只是**问**你了解一下」→「我只是**为**你了解一下」：同音字。
两者都是单字替换，不改原意方向；配合 `fix_names` 已修掉「精灵/京灵…」→「鲸灵」的专名错写。

## 线上真实日志（改造前，`~/.dsh/pet-voice/asr/transcripts.log`）

同一台机器、同一个 worker，真实请求耗时：2603 / 3128 / 4130 / 4443 / **19827 ms**（12 s 音频），
另有 5 次 12.00 s 的 `silent` 上传（录音跑到上限、整段判空）——「说完半天没反应」与
「不太说话也一直等」都能在这里对上。改后 bench 的最慢值是 1829 ms。

## 端点检测（说完多久提交）

| 参数 | 改前 | 改后 |
| --- | --- | --- |
| `tailSilenceMs`（说完→停止录音） | 1000 ms | **700 ms**（Siri 0.8 s，再快一点） |
| `noSpeechMs`（一直没人说话→放弃） | 6000 ms | **4000 ms** |

短句端到端因此再省约 300 ms；若真机切尾音（最后半个字被吃掉），把 `VadGate.kt` / `VoiceRecorder.kt`
里的 700 改回 800 即可，其余逻辑不用动。
