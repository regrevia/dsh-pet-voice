## 说明

- `start`/`delta`/`final`/`end` 都是相对**同一次 POST 发出前**的墙钟，SSE 帧按到达时刻记，不含客户端渲染。
- 「首个信号」= min(SSE 首帧, HTTP 200)：这才是手机能开始动作的时刻；`ack` 与 `start` 单看会在两种调度先后之间跳变（同一次跑里能差 300ms 以上），不宜当回归指标。
- 文本路径是**真派发一轮**（会跑模型、花 token）；只落固定的安全会话，不含用户会话。
- ASR 冷启动单列：worker 没在跑时 `/api/asr` 的 `running=false`，第一轮会把它拉起来（十几秒量级）；本机 worker 常驻时量到的都是热路径。
- TTS 两行是两种事：新句走 stream.py 现合成（量首字节），固定句量缓存命中；后者 1ms 是预期。
- 复现：`node scripts/pet-bench.mjs --n 10 --write`（宿主端口变了就加 `--base http://127.0.0.1:<port>`）。

> 本文件整篇由脚本生成，`--write` 会覆盖。更细的 ASR / TTS 脚本级基准（冷启动、后端对比、mlx 根因）在 [`docs/pet-bench-asr.md`](pet-bench-asr.md)，那一份不归脚本管。
