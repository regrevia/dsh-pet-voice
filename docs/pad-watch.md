# 平板屏幕回看（滚动录制，只留最近 3 分钟）

排查「点了没反应」「手感和预期不一样」「尺寸跳一下」这类只有肉眼看得出的事，需要看到平板上的画面本身。做法：让平板自己一直在录，只留最近 3 分钟，需要的时候再拉下来看。

默认是静默的：录完就滚掉，没人要求就不拉、不看、不上传。

## 用法

```bash
bash scripts/pad-watch.sh start            # 后台开始在平板上滚录（默认 15ca9736）
bash scripts/pad-watch.sh status           # 在不在录、设备上有几段、占多少
bash scripts/pad-watch.sh pull 180         # 只在被要求时跑：把最近 3 分钟拉到 local/rec/
bash scripts/pad-watch.sh stop             # 停
```

- 分段：每段 20 秒（`screenrecord` 每次到点自己退出，循环接着录），所以每段都是能直接播的 mp4。
- 保留：按文件数保留最近 12 段（约 4 分钟）再按时间兜底删，稳定压在 3 分钟量级。
- 位置：设备上 `/sdcard/pet-watch/`，电脑上 `local/rec/`（`local/` 不进仓库）。

## 成本

720p / 30fps / 4Mbps：

- CPU 约 3–6%，走硬件编码器，不占 GPU；
- 电量约 2–4%/小时（亮屏时才录，息屏就是几百字节/段）；
- 设备存储约 60–100MB 封顶（12 段 × 20 秒，旧的自己删）；
- 不经过电脑、不走网络，所以不耗流量、不耗宿主机。

想更省：`PW_FPS=15 PW_BITRATE=2M PW_SEG_SECONDS=30 bash scripts/pad-watch.sh start`。

## 已知行为

- 画面不动时几乎不产帧（编码器丢重复帧）：静态段只有几帧/几 KB，一有操作就回到正常帧率（实测 20 秒段 467 帧 / 250KB）。翻看时不影响判断，看的是「做了什么」。
- 录制期间设备上只应有一个 `screenrecord`；脚本每轮开始会清掉上一轮残留的（主机侧被 kill、adb 掉线时会留）。
- 加密窗口（部分银行/密码框）录不到，这是系统的限制。
- 拉下来的段用 `ffprobe` 即可看时长/帧数；要看画面就 `ffmpeg -i x.mp4 -vf fps=2 frame-%02d.png`。
