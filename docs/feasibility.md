# 可行性调研报告

> 问题：做一个「随身宠物」——屏幕显示像素风鲸鱼娘、支持实时对话、能互相聊天、语音流畅、可以放到手表/音箱/自研硬件上、语音唤醒随时聊。
> 结论：**可行**。核心链路已在本机跑通并量化；剩下的风险集中在硬件侧的 AEC 与续航，不在软件侧。

## 1. 需求拆解与判定

| 需求 | 判定 | 依据 |
| --- | --- | --- |
| 像素风鲸鱼娘、看着舒服 | ✅ 已做 | `demo/public/pet.js`，112×112 逻辑像素、`image-rendering: pixelated`，在手机上按 3× 整数倍放大 |
| 实时对话、延迟可接受 | ✅ 已做 | 说完→出声 1.2–1.4s（实测：VAD 500–700 + ASR ~250 + LLM 265 + TTS 首句 ~300） |
| 「互相聊天」（多轮、接话） | ✅ 已做 | 服务端 persona + 最多 14 轮上下文；接 DSH 后有记忆和工具 |
| 流畅语音（不卡、能打断） | ✅ 已做 | 句级流水线 + TTS 并行预取 + `utt_id` 打断；本地判停 <100ms |
| 手机负责路由 | ✅ 已做 | 手机浏览器/PWA 只做屏+麦+喇叭，PC 做全部计算（`demo/`） |
| 蓝牙连接 | ⚠️ 有条件 | 手机→PC 走 Wi-Fi（延迟更低）；蓝牙 A2DP 只有 ~250kbps 且单向播放，HFP 双向但音质差 8kHz；**ESP32-S3 只有 BLE，没有经典蓝牙** |
| 智能音箱远程接入 | ❌ 不可行 | 小爱/天猫精灵/HomePod 均不开放原始麦克风流，只能被 DLNA/AirPlay「投放」→ 只能当喇叭，不能当麦克风 |
| 智能手表 | ⚠️ 只能当第二屏 | Wear OS 后台拿不到麦克风（仅「使用中/前台」）；Galaxy Watch9 ¥2499+ / OPPO Watch X ¥2299–2999，且要 $25 开发者费 + 12 人/14 天封闭测试才能上架 |
| 语音唤醒 | ⏳ 未做（方案明确） | 本地 KWS：ESP-SR（ESP32 上 200KB 内）或 sherpa-onnx（PC/手机）；云端唤醒词要常在线、不划算 |
| 「像智能硬件」的体感 | ⏳ 需硬件 | 软件层已具备（全屏 PWA + 全屏无地址栏 + 像素画 + 声呐光效）；真正的硬件感来自 ESP32 挂坠 |

## 2. 架构（为什么这样切）

三层：**设备层（屏/麦/喇叭）— 网关层（编解码、ASR、TTS、LLM 代理）— 大脑层（DSH/LLM/记忆）**。

关键是「媒体在设备、计算在电脑」：设备端只跑像素绘制和 Opus 编解码，CPU 占用极低（旧手机、ESP32 都扛得住）；所有重活留在电脑，换模型、换人格、加记忆都不用碰固件。

细节、时延预算、语音协议见 [architecture.md](architecture.md)。

## 3. 实测数据（全部可复现）

| 项 | 结果 | 复现 |
| --- | --- | --- |
| LLM 首字（CoT 关） | 265 ms；短回复全文 488 ms | `curl -N -X POST localhost:8787/api/chat …` |
| LLM 首字（CoT 开，默认） | 2.4–4.1 s，且 `finish_reason:"length"` 常见 | `bench/llm_bench.py` |
| ASR whisper base / CPU | 183.7 ms（3s）/ 204.2 ms（4.23s，RTF 0.048），模型加载 374.6 ms | `bench/asr_bench.py` |
| ASR HTTP 端到端 | 401 ms / 4.2s 音频（含 ffmpeg webm→16k wav） | `POST /api/asr` |
| TTS `say` CLI | 643.5 ms/17字、670.6 ms/46字（几乎全是进程启动） | `bench/tts_bench.py` |
| TTS 进程内 `AVSpeechSynthesizer` | 首包 155.8–161.4 ms；守护进程 172–337 ms/句 | `bench/tts_avspeech.swift` |
| VAD 判停 | 尾音 500–700 ms；hangover 300ms 会把 2.4s 的句子切断，≥500ms 对齐误差 −20ms | `bench/vad_bench.py` |
| Opus 20ms 帧 | 23.0 kbps ≈ 57 B/帧，比 PCM 省 17× | `bench/codec_bench.py` |
| 云端价格（参考） | 阿里百炼 Paraformer 0.288 元/小时；流式 ASR 3.50 元/小时；流式 TTS 1.00 元/万字 | 官方定价页（见 voice.md） |

> MPS 跑 whisper 不可用（更慢），ARM 上 whisper.cpp / sherpa-onnx 会更省，但本机装不上，上面的 PyTorch 数字可视为**上界**。

## 4. 硬件方案与 BOM（推荐形态：ESP32-S3 圆屏挂坠）

| 件 | 型号 | 估价 |
| --- | --- | --- |
| 主控 | ESP32-S3-WROOM-1 N8R2（8MB Flash / 2MB PSRAM） | ¥25 |
| 屏 | 1.28″ GC9A01 240×240 圆屏（SPI） | ¥25–35 |
| 麦克风 | ES7210 双麦模组（带 AEC 参考通道） | ¥30–45 |
| 功放 | MAX98357A + 小喇叭 | ¥10–15 |
| 电池 | 1000 mAh 锂电池 + 充电管理 | ¥15–20 |
| 其他 | 振动马达、外壳（3D 打印）、PCB、杂项 | ¥45–90 |
| **合计** | 45×45×16 mm，45–60 g，续航 3–6 h | **¥150–260** |

想跳过打板（价格 2026-10-24 从官方页核实）：
- **先验证语音**：[ESP32-S3 AI Smart Speaker](https://www.waveshare.com/esp32-s3-audio-board.htm) **$15.99≈¥115** —— 双麦 ES7210（降噪 + AEC）+ ES8311 + 喇叭座，无屏，`xiaozhi-esp32` 已有板级配置；
- **一体原型**：[ESP32-S3-Touch-LCD-1.85](https://www.waveshare.com/esp32-s3-touch-lcd-1.85.htm) **$25.99≈¥190** —— 1.85″ 360×360 圆屏 + 单麦 + 附 8Ω 2W 喇叭 + 充电 + RTC，固件已支持（单麦只有软件 AEC → 建议半双工）；
- ⚠️ **1.28 不能当语音板**：$20.29–21.99 的 [Touch-LCD-1.28](https://www.waveshare.com/esp32-s3-touch-lcd-1.28.htm) 只有屏/触摸/IMU/充电，**没有麦、没有编解码、没有功放**。

固件别从零写：`xiaozhi-esp32` 的 `boards/` 下已有 53 个板型目录（微雪一家 44 个变体），改 Wi-Fi + 我们的 WS 协议即可。完整选型与采购入口见 [hardware.md](hardware.md)。

| 阶段 | 内容 | 工期 | 产出 |

## 6. 风险清单

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| ESP32 双麦 AEC 实际效果未实测（唯一关键未知） | 外放时自己说话被听进去 | 先买 Waveshare 板验证；不行就半双工（播完再听）+ 耳机口 |
| 续航 3–6h 偏短 | 一天要充一次 | 加大电池 / 屏幕 30fps 降到 15fps / 息屏只留声音 |
| 唤醒词误触 | 半夜突然说话 | 本地两级门限（能量+关键词）+ 静音时段 |
| 云端 ASR/TTS 成本 | 长期在线贵 | 本地引擎优先，云端只做兜底 |
| 局域网安全 | 谁都能连网关说话 | 插件形态强制 `ctx.connection.admit(req)`；签名 token |
| macOS 限定 | 换 PC 要改 TTS | Linux 用 `espeak-ng`/云 TTS，接口不变 |

## 7. 一句话总结

**软件侧已经证明能做到 1.3 秒内回话、可打断、可装进口袋（旧手机）；硬件侧只剩一块 ¥150–260 的 ESP32-S3 板子和两周固件，把「手机」换成「挂坠」。智能音箱和手表这条路走不通，不用再试。**
